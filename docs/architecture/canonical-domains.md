# Canonical domains

Weave is a provider-neutral organization collaboration suite. Members work in Weave-owned domains; admins and operators govern provider selection, readiness, policy, migration, audit, and diagnostics behind those domains. A domain is therefore a product contract, not a provider screen.

Canonical domains give implementers one vocabulary for client surfaces, backend facades, Admin Console readiness, provider adapters, audit events, and acceptance evidence. Provider-specific objects may enrich a domain, but they must not leak into normal member setup or navigation.

## Domain registry v1

| Domain | Purpose | Canonical objects | Provider candidates and profiles | Portability risks |
| --- | --- | --- | --- | --- |
| `platform-identity` | Sign-in, immutable subject resolution, organizations, groups, roles, invitations, sessions, workload clients, and admin lifecycle inputs. | Keycloak subject, upstream identity-source ref, group, role, capability profile, login session. | Keycloak is the fixed platform authority; OIDC/SAML and LDAP/AD systems attach upstream through federation or brokering and never enter the provider patch panel. | Email rename, subject collision, nested groups, guest identities, deleted/recreated accounts, last-admin lockout, upstream mapper drift. |
| `people` | Weave person directory and organization membership independent of identity-provider internals. | Person, profile, contact method, avatar reference, organization unit, external contact, identity account link. | SCIM, OIDC profile, LDAP/AD directory, HRIS import, or Weave-owned directory profile. | Identity/person merge, stale profiles, guest lifecycle, visibility rules, duplicate contacts. |
| `spaces` | Cross-domain context anchor for rooms, projects, teams, and governed work surfaces. | Space, space membership, space role, domain binding, provider binding map, context policy, default surface, archive state. | Weave-owned Space manifest with chat channels, board projects, file roots, calendar resources, calls, and decision ledgers as adapters. | Split ownership across providers, renamed or deleted upstream containers, partial provisioning, inconsistent membership propagation. |
| `chat` | Conversations, threads, messages, reactions, mentions, read state, retention, encryption state, and attachments as contextual communication. | Conversation, message, thread, reaction, mention, attachment reference, membership, read receipt, edit/delete event, retention policy, encryption state, opaque encrypted envelope, device reference. | Matrix/Synapse-class dogfood adapter behind the Weave Matrix facade; candidates include Slack-like, Teams-like, Talk-like, or provider-native chat adapters. | Thread semantics, client-owned E2EE recovery and key export, attachment retention, broadcast messages, provider-native cards and mentions. |
| `files` | File storage, folders, binary transfer, permissions, versions, share links, locks, trash, and checksum verification. | Drive, folder, file, file version, blob reference, permission, share link, lock, trash entry, checksum. | Nextcloud/WebDAV-class dogfood adapter behind the Weave WebDAV facade; candidate adapters include SharePoint/OneDrive-like, S3-compatible storage, SMB, or Weave-owned file service. | Permissions, public links, versions, locks, external users, checksum mismatch, quota and binary transfer feasibility. |
| `documents` | Collaborative document sessions and document metadata separated from raw file storage and editor providers. | Document, editor session, editor provider, lock, co-authoring state, version reference, guarded WOPI-style launch contract. | Collabora/OnlyOffice-style profiles first; candidate adapters include Microsoft 365/Graph-like, Google Workspace-like, or provider-native document APIs. | Coauthoring fidelity, comments/suggestions, native formats, external share links, conversion loss, unsafe editor launch. |
| `calendar` | Team/channel calendars, events, occurrences, recurrence, exceptions, attendees, resources, reminders, time zones, and meeting bindings. | Calendar, event, occurrence, recurrence rule, recurrence exception, attendee, resource, reminder, time zone, conference link. | Nextcloud/CalDAV-class dogfood adapter behind the Weave CalDAV facade; candidate adapters include Graph-like Calendar, Google Calendar-like, generic CalDAV-like, or Weave-owned team calendar. | RRULE fidelity, time zones, attendee responses, private events, resource booking, online meeting links. |
| `boards` | Work items, status, board/list workflow, dependencies, comments, attachments, custom fields, and decision links. | Board, list, task, status, assignee, watcher, comment, attachment reference, dependency, label, custom field, estimate, priority, milestone, sprint, workflow rule. | OpenProject-style adapter first plus placeholder contract parity; candidates include Jira-like, Planner-like, Deck-like, Vikunja-like adapters. | Custom fields, workflow transitions, status-vs-list semantics, multi-assignee semantics, comments/attachments, optimistic locking, bulk migration apply. |
| `calls` | Meeting identity, MatrixRTC slots/membership, authorized participants and roles, media sessions, recordings, transcripts, captions, consent, retention, and meeting context references. | Meeting, Matrix room, RTC slot, RTC member, device binding, media session, SFU authorization, recording, transcript, caption, consent record, retention policy. | MatrixRTC Profile 0 northbound; LiveKit is the first replaceable SFU adapter; Teams/Meet/external links remain southbound adapters. | Matrix Native OAuth separation, RTC Authorizer checks, MatrixRTC media E2EE, consent, short-lived SFU tokens, accessibility, external link ownership, provider outages. |
| `decisions` | Durable decisions, approvals, references, and audit-friendly reasoning connected to Spaces. | Decision, proposal, vote/approval, rationale, link, evidence reference, supersession. | Weave-owned decision ledger first; adapters may link to issue trackers, docs, or governance tools. | Legal retention, stale links, conflicting decision sources, permissioned rationale. |
| `notifications` | Product-level notification preferences, routing, digesting, and delivery evidence. | Notification, preference, channel, digest, delivery attempt, subscription. | Weave-owned notification facade with email, push, Matrix, Slack/Teams, or webhook transports. | Duplicate delivery, unsubscribe semantics, cross-provider identity, rate limits, audit redaction. |
| `health` | Admin/operator readiness, provider diagnostics, support-safe remediation, backup/restore, and release evidence. | Readiness card, diagnostic, support bundle, backup job, restore drill, evidence item, audit reference. | Backend-owned health facades across all provider categories; Admin Console Workspace Health as the operator surface. | Raw provider leakage, secrets in diagnostics, false green states, missing restore evidence, member/admin boundary violations. |
| `weaver` | Optional per-user personal-assistant runtime generated from organization policy and user consent. | Runtime profile, tool grant, skill package, sandbox, approval policy, audit event, opt-in state. | OpenClaw-derived isolated profile only; no alternative runtime is approved in Sprint 8. | Over-broad tools, secret exposure, cross-user data bleed, missing group-chat consent, unaudited actions, runtime execution before governance exists. |

## Contract rules

1. **Provider-neutral member surface**: Normal members see Weave domains and effective capability states only. Provider setup, secrets, migration, readiness, audit, and diagnostics remain backend/admin/operator side.
2. **Spaces anchor cross-domain work**: A Space is the stable organization context that links chat, files, documents, boards, calendars, calls, decisions, notifications, people, and policy. Provider containers attach to a Space; they do not define the product boundary.
3. **People and platform identity stay separate**: `platform-identity` resolves authentication and immutable Keycloak subjects. `people` models the human or service participant in Weave. Email addresses are not primary identity keys.
4. **Deny by default**: Unknown provider states, roles, groups, capabilities, adapter claims, or runtime grants fail closed into support-safe states.
5. **No preview member UX**: Dogfood-production surfaces must be ready, unavailable, degraded, disabled by policy, not configured, or coming later by explicit product contract. Scaffold and preview states are not member-facing release claims.
