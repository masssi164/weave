# Canonical domains

Weave is a provider-neutral organization collaboration suite. Members work in Weave-owned domains; admins and operators govern provider selection, readiness, policy, migration, audit, and diagnostics behind those domains. A domain is therefore a product contract, not a provider screen.

Canonical domains give implementers one vocabulary for client surfaces, backend facades, Admin Console readiness, provider adapters, audit events, and acceptance evidence. Provider-specific objects may enrich a domain, but they must not leak into normal member setup or navigation.

## Domain registry v1

| Domain | Purpose | Canonical objects | Provider candidates and profiles | Portability risks |
| --- | --- | --- | --- | --- |
| `identity` | Sign-in, immutable subject resolution, groups, roles, and admin lifecycle inputs. | Subject, identity source, group, role, capability profile, login session. | Keycloak realm/client as the current desired-state profile; future OIDC, SAML, SCIM/LDAP, Entra ID, Authentik, or Auth0 adapters. | Email rename, subject collision, nested groups, guest identities, deleted/recreated accounts, last-admin lockout. |
| `people` | Weave person directory and organization membership independent of identity-provider internals. | Person, membership, profile, contact method, team, guest, service account reference. | SCIM, OIDC profile, LDAP/AD directory, HRIS import, or Weave-owned directory profile. | Identity/person merge, stale profiles, guest lifecycle, visibility rules, duplicate contacts. |
| `spaces` | Cross-domain context anchor for rooms, projects, teams, and governed work surfaces. | Space, membership, role binding, linked channel, linked board, linked calendar, linked file root, decision ledger reference. | Weave-owned Space manifest with Matrix/Teams/Slack channels, OpenProject projects, Nextcloud/SharePoint folders, and calendar resources as adapters. | Split ownership across providers, renamed or deleted upstream containers, partial provisioning, inconsistent membership propagation. |
| `chat` | Conversations, threads, messages, reactions, presence, and attachments as contextual communication. | Conversation, message, thread, reaction, attachment, presence, membership. | Matrix/Synapse first; candidate adapters include Slack, Microsoft Teams, Nextcloud Talk, or provider-native chat APIs. | Thread semantics, E2EE recovery, attachment retention, broadcast messages, provider-native cards and mentions. |
| `files` | File storage, folders, binary transfer, permissions, versions, and share state. | Drive, folder, file, file version, permission, share, lock, storage quota. | Nextcloud Files/WebDAV first; candidate adapters include SharePoint, OneDrive, S3-compatible storage, SMB, or Weave-owned file service. | Permissions, public links, versions, locks, external users, quota and binary transfer feasibility. |
| `documents` | Collaborative document sessions and document metadata separate from raw file storage. | Document, edit session, comment, suggestion, coauthor presence, version, export. | Nextcloud/Collabora or OnlyOffice profile; candidate adapters include Microsoft 365/Graph, Google Workspace, or provider-native document APIs. | Coauthoring fidelity, comments/suggestions, native formats, external share links, conversion loss. |
| `calendar` | Team/channel calendars, events, availability, resources, and meeting bindings. | Calendar, event, attendee, recurrence, availability, resource, meeting reference. | Nextcloud CalDAV first; candidate adapters include Microsoft Graph Calendar, Google Calendar, generic CalDAV, or Weave-owned team calendar. | RRULE fidelity, time zones, attendee responses, resource booking, online meeting links. |
| `boards` | Work items, status, board/list workflow, dependencies, comments, and decision links. | Board, list, task, status, assignee, comment, attachment, dependency, custom field. | OpenProject first; placeholder/null adapter for disabled state; candidates include Jira, Microsoft Planner, Nextcloud Deck, Vikunja. | Custom fields, workflow transitions, multi-assignee semantics, comments/attachments, optimistic locking, bulk migration apply. |
| `calls` | Meeting join/host capability, media sessions, participant state, recording/captions policy, and consent. | Meeting, media session, participant, token grant, recording, caption, consent record. | LiveKit token/readiness facade first; candidate adapters include Jitsi, Zoom, Microsoft Teams meetings, Google Meet, external meeting links. | E2EE boundary, recording consent, token grants, accessibility, external link ownership, provider outages. |
| `decisions` | Durable decisions, approvals, references, and audit-friendly reasoning connected to Spaces. | Decision, proposal, vote/approval, rationale, link, evidence reference, supersession. | Weave-owned decision ledger first; adapters may link to issue trackers, docs, or governance tools. | Legal retention, stale links, conflicting decision sources, permissioned rationale. |
| `notifications` | Product-level notification preferences, routing, digesting, and delivery evidence. | Notification, preference, channel, digest, delivery attempt, subscription. | Weave-owned notification facade with email, push, Matrix, Slack/Teams, or webhook transports. | Duplicate delivery, unsubscribe semantics, cross-provider identity, rate limits, audit redaction. |
| `health` | Admin/operator readiness, provider diagnostics, support-safe remediation, backup/restore, and release evidence. | Readiness card, diagnostic, support bundle, backup job, restore drill, evidence item, audit reference. | Backend-owned health facades across all provider categories; Admin Console Workspace Health as the operator surface. | Raw provider leakage, secrets in diagnostics, false green states, missing restore evidence, member/admin boundary violations. |
| `weaver` | Optional per-user personal-assistant runtime generated from organization policy and user consent. | Runtime profile, tool grant, skill package, sandbox, approval policy, audit event, opt-in state. | OpenClaw-derived isolated profile only; no alternative runtime is approved in Sprint 8. | Over-broad tools, secret exposure, cross-user data bleed, missing group-chat consent, unaudited actions, runtime execution before governance exists. |

## Contract rules

1. **Provider-neutral member surface**: Normal members see Weave domains and effective capability states only. Provider setup, secrets, migration, readiness, audit, and diagnostics remain backend/admin/operator side.
2. **Spaces anchor cross-domain work**: A Space is the stable organization context that links chat, files, documents, boards, calendars, calls, decisions, notifications, people, and policy. Provider containers attach to a Space; they do not define the product boundary.
3. **People and identity stay separate**: `identity` resolves authentication and immutable provider subjects. `people` models the human or service participant in Weave. Email addresses are not primary identity keys.
4. **Deny by default**: Unknown provider states, roles, groups, capabilities, adapter claims, or runtime grants fail closed into support-safe states.
5. **No preview member UX**: Dogfood-production surfaces must be ready, unavailable, degraded, disabled by policy, not configured, or coming later by explicit product contract. Scaffold and preview states are not member-facing release claims.
