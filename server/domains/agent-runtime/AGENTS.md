# Agent Runtime ownership

Apply root and Server instructions and the shared Java/Spring standard. This is a future
product domain. Its actual serving graph, controllers, settings, state adapter, specialized
transport and operator code belong to the root runtime; model/persistence/provider/security
retain useful compiled boundaries. Buildability is separate from release inclusion. Do not
claim reduced App composition or production-ready future execution from a passing library check.

Keep `model` framework-free and dependencies inward. Shared Keycloak/session/release workload
security belongs to Core; do not copy it or pull future runtime logic into Core. Publish actual
module-local Boot imports, preserve the servlet/non-web split, and keep providers offline during
metadata/AOT graph construction. Do not hide required missing beans behind conditional fallbacks.

Preserve tenant/profile/workload binding checks, exact token policies, synchronization and
transaction boundaries. Mounted secrets must fail closed at serving readiness/first use. Reads
must not chmod or initialize a read-only key store. Key initialization and rotation remain
explicit guarded operator actions. Domain readiness contributions retain support-safe copy and
perform no probes during construction.

Run owning unit and context lanes separately through the shared library mechanics. Keep genuine
App-coupled HTTP/PostgreSQL harnesses where they compile without reverse dependencies, preserving
their assertions and PostgreSQL task registration. Update source-inspection paths for every
physical move; do not use source aliases, duplicate classes or forwarding production facades.
